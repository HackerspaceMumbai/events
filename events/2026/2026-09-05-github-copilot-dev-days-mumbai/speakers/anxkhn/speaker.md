# One Interface, Infinite Agents: Using Copilot with Omnigent

## Abstract

Developers often move between coding agents when they hit rate limits or need a different model, but copying the last prompt loses the investigation that led there. This session explains how Omnigent keeps conversations, tool calls, diffs, test results, usage, and session lineage in one work record. A live demo follows a bug fix from GitHub Copilot into the browser, then forks the session to Codex for an independent review.

## Key Takeaways

- Models, harnesses, agents, and meta-harnesses solve different parts of the coding-agent workflow.
- Session forks can preserve conversation and tool history, but provider caches and private runtime state do not transfer.
- A receiving agent should verify the current workspace, diff, and test result instead of trusting a copied summary.
- Prompts express intent, policies gate tool calls, and sandboxes isolate execution at different layers.
